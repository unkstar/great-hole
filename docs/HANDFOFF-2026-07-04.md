## FEC Batching Debug Status

### Problem
TUN `TryRead()` (non-blocking `read_some`) always returns EAGAIN/would_block immediately after `co_await Read()`. This caused the original reader fiber to only get 1 packet per cycle, keeping all batches at K=1 (REPEAT mode only).

### Fix Applied
Two changes to `src/core/FecPipeline.cpp`:

1. **REPEAT threshold**: Changed `if (pkt_count == 1 && adaptive_ratio > 0.0f)` to `if (pkt_count == 1)` — allows copies=1 with `repeat_ratio_min=0`.

2. **First-packet-time tracking**: Main loop now tracks when the first packet arrived (`first_packet_time`), then waits `timeout_ms` from that moment before draining. Reader fiber continues accumulating during the wait. This replaces the old unconditional `co_await timer->async_wait(timeout_ms)`.

### Current State
- **Batching WORKS**: 4-12 packets per batch observed in logs ("decoded group 45 with 9/9 symbols")
- **Throughput with timeout=2ms + batching**: ~9 Mbps (too slow — RaptorQ encode for K>1 adds latency, combined with timer overhead)
- **Throughput with timeout=0ms (no batching)**: ~43 Mbps (REPEAT path, fast)
- **Throughput with nofec (plain pipeline)**: ~59 Mbps (baseline)

### Root Cause of Remaining Slowdown
With timeout=2ms and batching, the main loop's timer accumulation creates significant idle time:
- First packet wait: `timeout_ms` (2ms)
- Accumulate: `deadline - now` (~0-2ms)
- Between batches: encode/send blocks reader fiber (same thread)
Total per-batch: ~3-4ms, limiting to ~250-333 batches/sec. Even at 12 packets/batch, that's only 3000-4000 pps = ~34-45 Mbps theoretical.

The nofec pipeline has zero idle time: Read → Write → Read → Write (continuous).

### Next Steps
1. **Optimize batch accumulation**: Instead of separate timer phases, use a single `co_await _In->Read()` with a Cancel that fires after timeout — this would eliminate the timer overhead entirely
2. **Or**: Use omni-fiber `Select` to race Read against timer (failed to compile before — needs investigation of awaiter interface)
3. **Or**: Accept single-packet REPEAT mode with copies=1 (43 Mbps) for production, use RaptorQ only when actual packet loss is detected
